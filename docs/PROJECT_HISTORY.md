# 「権田原佃煮店」教材パッケージ 制作・開発経緯録

本ドキュメントは、教育用教材パッケージ「権田原佃煮店」の企画立ち上げから、要件定義、教材としてのブラッシュアップ、実装、環境最適化、および不具合修正に至る全プロセスと設計思想の変遷を記録したものです。

---

## 1. プロジェクト発足と初期構想

### 1.1. 発足の背景と目的
Webエンジニア、QAテスター、ディレクター等の技術研修において、既存の教材は「綺麗に整理されすぎている」ことが多く、受講生が実務現場に配属された際に直面する「要件の曖昧さ」「仕様書と実装の乖離」「レガシーコードの地雷」に太刀打ちできないという課題がありました。
本プロジェクトは、実務で遭遇するアンチパターンを凝縮した**「最も痛い目を見る実践型教材」**を制作することを目的としてスタートしました。

### 1.2. 当初の必須要件（3大コンテンツ）
1. **雑に作られバグのあるサンプル通販サイト「権田原佃煮店」** (Docker上で動作、Laravelで実装)
2. **雑に顧客からヒアリングしたようなサイト企画書とサイトマップ** (見栄えだけ一丁前なPowerPoint)
3. **雑に作られたAPIドキュメント** (見た目だけSwagger風)

---

## 2. 企画・設計の深化プロセス

### 2.1. 企画書・サイトマップの「二系統化（建前・本音）」への進化
当初は居酒屋ヒアリングの生々しいツッコミどころ（動画バーン音ドーン、常連合言葉で半額、生モノは電話で断る）をそのままスライドに記載していましたが、**「より実務の闇と教育的価値を最大化する」**ため、企画書を二系統に再編しました。

* **🔒 社内検討用メモ (`docs/planning/gondawara_dx_internal_memo.pptx` / `internal_presentation.html`)**:
  * 店主・権三氏の生の声（居酒屋トーク）と、制作側の手抜き方針を赤裸々に記録した「本音」の資料。
* **★ 顧客提示用提案書 (`docs/planning/gondawara_dx_proposal.pptx` / `presentation.html`)**:
  * 店主の曖昧な要望を企画側が拡大解釈し、マーケティング用語（「シズル感の最大化」「イマーシブ演出」「ゲーミフィケーション」「ハイタッチ接客」）で飾り立てた「建前」の資料。
  * システム要件定義には、現物コードと真逆に乖離した「排他制御」「インボイス制度完全準拠」「OWASP Top 10準拠」などの極めて真っ当な設計を記載。
  * スケジュールは、ビジネス文章としてスマートでありながら、バッファがゼロで少しの遅延で即炎上する「絶妙に守れそうで守れない高効率アジャイル工程」を設計。

### 2.2. API仕様書の「網羅的＋だいたい合ってる間違い探し」への高度化
初期のAPI仕様書はURLが違ったり説明が殴り書きだったりと「粗すぎて一発で嘘だとわかる」構成でした。
テスター育成・QA研修として成立させるため、以下の方針へ刷新しました：
* **全主要7エンドポイントを網羅した本格的なOpenAPI 3.0 / Swagger UI仕様書の作成**
* **「90%は仕様書通りに動くが、テスト技法（境界値分析、同値分割、データ型検証、異常系）を用いて初めて検出できる13箇所のリアルな不整合」**を実装と仕様書の間に対比配備。
* 指導者向けに採点基準とチェックリストを完備した [docs/TEACHER_GUIDE.md](TEACHER_GUIDE.md) を整備。

## 3. 実装およびトラブルシューティングの経緯

### 3.1. Docker環境およびLaravelアプリケーションの構築
* **インフラ**: Nginx, PHP 8.2-FPM, MySQL 8.0, Mailpit（疑似SMTPサーバー）を Docker Compose で構成。
* **アプリケーション**: 創業120年の老舗感を再現した昭和レトロ和風デザインのBladeテンプレート群、および全業務ロジック・バグを集約した1500行の神コントローラ（`GondawaraShopController.php`）を構築。
* **仕込みバグ10選**:
  1. カート数量のマイナス値入力による返金・無料購入バグ
  2. 画面・DB間での消費税端数処理の不一致（四捨五入/切り捨て/切り上げ）
  3. 排他制御欠如による在庫マイナス販売（レースコンディション）
  4. 大文字・小文字判定の甘さによる同一クーポンの無限重複適用
  5. 商品検索窓における生SQL結合インジェクション (`' OR '1'='1`)
  6. レビュー欄のStored XSS (`{!! $review->comment !!}`)
  7. 注文詳細URLのID直接参照によるIDOR（他人の個人情報漏洩）
  8. URLパラメータによる管理画面の認証バイパス (`?admin_bypass=1`)
  9. 受注一覧ループにおけるN+1クエリ問題
  10. 本番デバッグモード露出 (`APP_DEBUG=true`)

### 3.2. 直面した技術課題と解決の軌跡

#### ① Git管理およびリモートリポジトリ連携
* **事象**: ローカル環境でGit初期化時、サンドボックスによる `~/.gitconfig` へのアクセス制限が発生。
* **対応**: 適切な実行権限モードでGitリポジトリを初期化し、リモート（[https://github.com/umberbyte/gondawaraStore.git](https://github.com/umberbyte/gondawaraStore.git)）を設定、`main` ブランチへ初回プッシュを実施。

#### ② ポート競合の回避（8000番台 &rarr; 9000番台）
* **事象**: ホストマシン上で一般的な開発用8000番台ポートが他プロジェクトと競合。
* **対応**:
  * Webサーバー（Nginx）: `8080` &rarr; `9080`
  * Mailpit（Web UI）: `8025` &rarr; `9025`
  * `docker-compose.yml`, `src/.env`, `src/config/app.php`, `docs/api/`, `README.md` 全体のポート表記を9000番台へ一括更新。

#### ③ Docker Compose V2 警告対応
* **事象**: `docker compose` 実行時に `attribute 'version' is obsolete` の警告が出現。
* **対応**: 現代のCompose V2仕様（Compose Specification）に適合させ、最上位の `version: '3.8'` 属性を安全に削除。

#### ④ 基底コントローラ欠落による初期アクセスエラーの解消
* **事象**: サイトアクセス時に `Class "App\Http\Controllers\Controller" not found` が発生。
* **対応**: Laravelの基底コントローラ [`src/app/Http/Controllers/Controller.php`](file:///Users/gsgwr/.gemini/antigravity/scratch/gondawara-tsukudani/src/app/Http/Controllers/Controller.php) を追加配置。

#### ⑤ DB未マイグレーション時のフェイルセーフ設計
* **事象**: 初回起動直後、受講生が `migrate --seed` を実行する前にトップページや商品一覧を開くと500エラー（Table not found）になる懸念。
* **対応**: `GondawaraShopController` のデータ取得部に例外保護を導入し、DB初期化前でも画面レイアウトと初期化案内メッセージが安全に表示されるよう改善。

#### ⑥ ストレージ書き込み権限の最適化
* **事象**: Dockerコンテナ内のPHPプロセスがBladeキャッシュやログファイルを作成する際の Permission Denied リスク。
* **対応**: `src/storage` および `src/bootstrap/cache` に再帰的な書き込み権限（777）を付与。
